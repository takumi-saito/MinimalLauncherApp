# VRT の実行と差分レビュー

`vrt/expect/`（期待画像）と現状の描画を比較し、UI の意図しない変化を検出する。

## 手順

### 1. 比較を実行

```bash
./gradlew :app:vrtVerify
```

これは `vrt/actual/` と `vrt/diff/` を生成し、差分があれば失敗する。
（初回や `vrt/expect/` が空の場合は、まず「4. 期待画像を新規作成する場合」へ）

### 2. 差分が無かった場合

「VRT: N 件を比較しました。差分はありません」とだけ報告して終了する。余計な作業はしない。

### 3. 差分があった場合

失敗メッセージに差分のあったファイルが列挙される。**必ず Read ツールで `vrt/diff/` の画像を実際に見ること。** ファイル名だけで判断してはいけない。

差分画像は左から `Reference`（期待）| `Diff`（差分を赤で強調）| `New`（現状）の3枚並び。

見たうえで、今回の変更内容（`git diff`）と突き合わせて次を判断する:

- **意図した UI 変更か**（パディング調整、色変更、文字列変更など、変更内容から説明がつく）
- **表示崩れ・考慮漏れか**（触っていないはずの画面が変わった、テキストが見切れた、要素が重なった、ダークモードだけ壊れた、など）

判断結果をユーザーに提示する。何が・どこで・どう変わったかを具体的に述べること。差分画像を見ずに「意図した変更のようです」と推測で答えてはいけない。

### 4a. 意図した UI 変更だった場合

ユーザーの確認を取ってから期待画像を更新する:

```bash
./gradlew :app:vrtRecord
git add vrt/expect
```

コミットは変更本体と一緒にするか別にするかをユーザーに確認する。

### 4b. 表示崩れだった場合

期待画像は**更新しない**。どの画面のどこが崩れているか、原因として疑わしい箇所（`app/src/main/java/com/kireaji/minimallauncherapp/ui/compose/` 配下）を指摘して終了する。

### 期待画像を新規作成する場合（画面や状態を追加したとき）

```bash
./gradlew :app:vrtRecord
```

`vrt/expect/<device>/<screen>-<state>.png` が生成されるので、Read で内容を確認してからコミットする。

## 注意

- 期待画像は **macOS(arm64) + JDK 17 + Robolectric SDK 35** で記録されたもの。別環境で実行すると
  フォントのアンチエイリアスの違いで全件差分になる。
- `vrt/actual/` と `vrt/diff/` は gitignore されている。コミットしようとしないこと。
- 画面や状態を追加する手順は `docs/vrt.md` を参照。
